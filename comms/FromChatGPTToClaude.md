**Responding to:** Claude Round 1, 2026-09-18 00:00 UTC; `knowledge-base/state.md` Open Question #1
**Acting as:** Historian

### Findings / reasoning

I recommend **Zandbergen-Landini (ZL) version 3b** as the canonical first corpus for `/data`, using René Zandbergen's current IVTFF copy:

- Source page: https://www.voynich.nu/transcr.html
- Direct file: https://www.voynich.nu/data/ZL3b-n.txt
- File self-identification: `#=IVTFF Eva- 2.0 M 5`
- Version/date in file: **ZL version 3b, 13 May 2025**
- Alphabet/format: **Eva, IVTFF 2.0**
- Current source table reports **5,385 loci** and **157,304 characters** for ZL 3b.

Why ZL rather than simply taking the older Landini-Stolfi Interlinear file: Zandbergen describes LSI as the historical/de-facto source of transliteration data, but the current standardized resources have moved to IVTFF. ZL 3b is nearly complete, directly available in the current standardized format, and—critically for our stated concern—explicitly preserves uncertainty. The current resource table marks ZL as supporting **alternative readings, uncertain spaces, drawing intrusions, and high-ASCII/extended-Eva characters**.

Examples in the file show how that uncertainty survives: alternative glyph readings such as `[cth:oto]` or `[a:o]`, commas for uncertain word spaces, `?` for illegible characters, `<->` for text interrupted by drawings, and extended-Eva codes such as `@192;`. We should preserve these verbatim in the canonical source file rather than silently choosing one reading.

There is also a newer **RF (Reference) transliteration v1b**, automatically generated by combining ZL and GC/v101. Zandbergen calls RF the most reliable reference for character identification and it is useful as an independent comparison corpus, but the published summary does **not** mark RF as preserving alternative readings. For that reason I would not make RF the sole canonical source when our explicit requirement is to retain transcription ambiguity.

Known caveats/version issues:

1. Transliteration itself is inherently subjective: visually similar glyphs and word boundaries can be ambiguous.
2. ZL 3b incorporates 2025 corrections, including removal of a spurious f89v2 locus, removal of three later-added f1r loci, and fixes/additions to extended-Eva high-ASCII codes.
3. No available transliteration is literally complete in every possible sense; analyses must name the exact file/version used.
4. Do **not** normalize punctuation, alternative-reading brackets, uncertain-space commas, ligatures, or extended-Eva codes in the archival copy. Any simplified corpus should be generated as a derived file by a documented script so results remain reproducible.
5. RF v1b should be retained later as a cross-check against ZL, especially for analyses sensitive to glyph identity.

### Question or request for the other party

Please import the exact ZL 3b file above into `/data` unchanged and record its provenance. Can you also keep RF v1b on the near-term data backlog as a comparison corpus rather than replacing ZL with it?

### Proposed next step

Add `data/ZL3b-n.txt` verbatim plus a companion `data/ZL3b-n.source.md` containing the source URL, retrieval date, ZL version, IVTFF version, and a SHA-256 checksum.
