# Atomic EVA Glyph Sensitivity Check

Generated by `data/scripts/atomic_eva_glyphs.py`. Tests whether treating `ckh`, `cth`, `cph`, `cfh`, `ch`, `sh` as single atomic glyphs, instead of 2-3 separate characters, changes the character-level constraint finding from `statistician_pass1.py` / `language_baselines.py`.

**Not a claim of consensus.** This is one commonly-cited atomic-glyph grouping from the Voynich research literature, not the only one proposed. Deliberately NOT implemented here: `qo-` clustering, and `in`/`ii`/`iii` minim-group clustering -- both more contested, left as further extensions.

## Method

Same source as pass 1: `data/derived/ZL3b-normalized.txt` (39,026 tokens, already downstream of the normalize_eva.py first-option-kept policy -- that caveat still applies here unchanged). Each word is tokenized greedily, longest match first, against the atomic set `['ckh', 'cth', 'cph', 'cfh', 'ch', 'sh']`, falling back to single characters for everything else. Entropy (H1) and bigram conditional entropy (H2) are computed over the resulting glyph-token sequences, exactly analogous to the character-level calculation in `statistician_pass1.py` but with glyphs as the unit instead of characters.

## Results

- Character-level constraint ratio (reference, from existing Confirmed Findings): **0.4539**
- Atomic-glyph-level constraint ratio: **0.4247**
- Glyph alphabet size: 48 (vs. 42 literal characters in the pass-1 alphabet)
- Total glyph tokens: 176,471 (vs. 196,302 literal characters)
- Atomic multi-character glyph occurrences: 17,726 (10.0% of all glyph tokens)
- Glyph-level H1: 3.9679 bits, H2: 2.2827 bits

## Interpretation (numbers and method only, no meaning claims)

- If the atomic-glyph constraint ratio is close to the character-level one, the earlier finding is not an artifact of splitting single strokes into multiple characters. If it moves substantially, the character-level pass-1 and language-baseline results need the atomic-glyph version reported alongside them, not instead of them, since both representations are used in the literature.
- This check only changes how the Voynich side of the comparison is tokenized. It does not re-run the language baselines, which remain character-level for Latin/Italian since those languages don't have the same multi-character-single-stroke question. A fully fair atomic-vs-atomic comparison isn't possible across scripts this different -- flagged, not solved.
- `qo-` and minim-group (`in`/`ii`/`iii`) clustering remain unimplemented and are a real next step if this check shows atomic tokenization matters.
